# Задание 8. Управление нагрузкой и мониторинг шардов MongoDB

## 1. Метрики для выявления «горячих» шардов

Чтобы предотвратить перегрузку узлов, нужно собирать метрики с каждого шарда. Основные индикаторы:

### Операции в секунду (QPS) по шардам
- **Что смотрим**: количество запросов на чтение/запись на каждом шарде
- **Триггер**: если один шард обрабатывает >70% всех операций — явный перекос

### Нагрузка на оборудование
- **Что смотрим**: CPU, Disk I/O, RAM (особенно page faults — когда данные подтягиваются с диска)
- **Триггер**: CPU >80% или высокий Disk I/O на одном шарде при простаивающих остальных

### Распределение чанков
- **Что смотрим**: количество чанков коллекции на каждом шарде
- **Триггер**: разница в количестве чанков между шардами >10-20 штук

### Очереди запросов
- **Что смотрим**: длину очереди ожидания и количество активных соединений
- **Триггер**: резкий рост очереди — запросы копятся и не успевают обрабатываться

### Быстрая диагностика в консоли
```javascript
// Как распределены чанки
sh.status()

// Нагрузка в реальном времени (в терминале ОС)
mongostat --discover
mongotop
```

## 2. Механизмы устранения дисбаланса

### Шаг 1. Дробление и перемещение горячих чанков

Проблема: категория «Электроника» занимает один большой чанк, который не может разбиться автоматически, потому что шард-ключ включает уникальный `_id`.

**Решение**: принудительно разбиваем большой чанк на части и раскидываем по разным шардам.

```javascript
// 1. Находим середину чанка с электроникой
db.products.find({ category: "Electronics" }).limit(1).sort({ _id: 1 })

// 2. Дробим чанк пополам
sh.splitFind("shop.products", { category: "Electronics", _id: ObjectId("середина_чанка") })

// 3. Переносим часть на другой шард
sh.moveChunk("shop.products", { category: "Electronics", _id: ObjectId("граница_нового_чанка") }, "shard-02")
```

### Шаг 2. Настройка автоматического балансировщика

В MongoDB есть встроенный Balancer, который автоматически перемещает чанки при перекосе. Чтобы он не мешал работе в часы пик:

```javascript
// Включаем балансировщик
sh.startBalancer()

// Настраиваем окно активности (например, ночью с 2 до 6 утра)
use config
db.settings.update(
   { _id: "balancer" },
   { $set: { activeWindow: { start: "02:00", stop: "06:00" } } },
   { upsert: true }
)
```

### Шаг 3. Оптимизация шард-ключа (долгосрочное решение)

Если проблема повторяется, нужно изменить шард-ключ, добавив искусственное поле для дробления:

```javascript
// Добавляем поле для шардирования внутри категории
db.products.updateMany(
  { category: "Electronics" },
  { $set: { shard_suffix: { $mod: [{ $toInt: "$_id" }, 10] } } }
)

// Новый шард-ключ: категория + суффикс (разбивает электронику на 10 частей)
sh.shardCollection("shop.products", { category: 1, shard_suffix: "hashed" })
```
