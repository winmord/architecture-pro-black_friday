# Задание 7. Проектирование схем коллекций для шардирования данных

## 1. Коллекция orders

### Схема коллекции

```javascript
{
  _id: ObjectId,                    // уникальный идентификатор заказа
  client_id: string,                // идентификатор клиента
  order_date: Date,                 // дата и время оформления
  items: [                          // список товаров
    {
      product_id: ObjectId,
      product_name: string,
      price: number,
      quantity: number
    }
  ],
  status: string,                   // статус заказа (created, paid, shipped, delivered, cancelled)
  total_amount: number,             // общая сумма
  geozone: string,                  // геозона доставки
  created_at: Date,
  updated_at: Date
}
```

### Шардирование

- Шард-ключ: { client_id: 1, order_date: -1 }
- Стратегия: Составной ключ с диапазонной шардизацией

### Обоснование

1. Основные операции:
    - Быстрое создание заказов (INSERT)
    - Поиск истории заказов пользователя (SELECT по client_id, сортировка по дате)
    - Отображение статуса заказа (SELECT по _id)

2. Почему выбран такой шард-ключ:
    - client_id в качестве первой части ключа обеспечивает, что все заказы одного пользователя хранятся на одном шарде —
      идеально для запросов истории заказов
    - order_date как вторая часть позволяет эффективно сортировать заказы по дате и поддерживает TTL-индексы для
      архивных данных
    - Диапазонная шардизация позволяет эффективно распределять новые заказы во времени

3. Преимущества:
    - История заказов пользователя читается с одного шарда без scatter-gather операций
    - Создание заказа — точечная операция на один шард
    - Возможность эффективного шардинга по времени для архивации старых заказов
    - Можно добавлять диапазонные индексы для аналитики по времени

4. Примеры:

```javascript
// Создание индекса для шард-ключа (по клиенту и дате)
db.orders.createIndex({ client_id: 1, order_date: -1 });

// Включение шардирования
sh.shardCollection("shop.orders", { client_id: 1, order_date: -1 });

// Вторичные индексы для поиска нужных заказов
// Поиск по ID заказа (для отображения статуса)
db.orders.createIndex({ _id: 1, client_id: 1 });

// Поиск заказов по статусу (например, для обработки)
db.orders.createIndex({ status: 1, order_date: -1 });

// Поиск заказов по геозоне (для аналитики доставки)
db.orders.createIndex({ geozone: 1, order_date: -1 });

// Поиск по дате (для отчетов и архивации)
db.orders.createIndex({ order_date: -1 });

// TTL-индекс для автоматической архивации старых заказов (например, через 2 года)
db.orders.createIndex({ order_date: 1 }, { expireAfterSeconds: 63072000 });
```

## 2. Коллекция products

### Схема коллекции

```javascript
{
  _id: ObjectId,                    // уникальный идентификатор товара
  name: string,                     // наименование
  category: string,                 // категория товара
  price: number,                    // цена
  stock: [                          // остатки по геозонам
    {
      geozone: string,              // геозона (Москва, Екатеринбург и т.д.)
      quantity: number              // остаток в этой геозоне
    }
  ],
  attributes: {                     // дополнительные атрибуты
    color: string,
    size: string,
    // другие характеристики
  },
  created_at: Date,
  updated_at: Date
}
```

### Шардирование

- Шард-ключ: { category: 1, _id: 1 }
- Стратегия: Составной хешированный шард-ключ

### Обоснование

1. Основные операции:
    - Частые обновления остатков (UPDATE по _id)
    - Поиск по категориям и фильтрация по цене (SELECT по category + price)
    - Получение описания товара (SELECT по _id)

2. Почему выбран такой шард-ключ:
    - category — основное поле для поиска товаров, запросы по категориям будут попадать в один шард, что обеспечивает
      локальность данных
    - Добавление _id в составной ключ обеспечивает уникальность и равномерное распределение при вставке новых товаров
    - Хешированная стратегия для category предотвращает создание "горячих" шардов из-за популярных категорий

3. Преимущества:
    - Запросы фильтрации по категории и цене выполняются в пределах одного шарда
    - Обновления остатков по _id направляются точно на нужный шард
    - Равномерное распределение данных за счёт хеширования категорий

4. Примеры:

```javascript
// Создание индекса для шард-ключа (хешированный по категории + _id)
db.products.createIndex({ category: "hashed", _id: 1 });

// Включение шардирования
sh.shardCollection("shop.products", { category: "hashed", _id: 1 });

// Вторичные индексы для поиска товаров
// Поиск по категории с фильтрацией по цене
db.products.createIndex({ category: 1, price: 1 });

// Поиск по наименованию (текстовый поиск)
db.products.createIndex({ name: "text" });

// Поиск по атрибутам (цвет, размер)
db.products.createIndex({ "attributes.color": 1 });
db.products.createIndex({ "attributes.size": 1 });

// Для обновления остатков по геозоне
db.products.createIndex({ "stock.geozone": 1 });
```

## 3. Коллекция carts

### Схема коллекции

```javascript
{
  _id: ObjectId,                    // уникальный идентификатор корзины
  user_id: string,                  // идентификатор пользователя (опционально)
  session_id: string,               // идентификатор сессии для гостей (опционально)
  items: [                          // список товаров
    {
      product_id: ObjectId,
      quantity: number,
      added_at: Date
    }
  ],
  status: string,                   // "active", "ordered", "abandoned"
  created_at: Date,
  updated_at: Date,
  expires_at: Date,                 // TTL для автоматической очистки
  total_items: number,              // денормализованное поле для оптимизации
  total_price: number               // денормализованное поле для оптимизации
}
```

### Шардирование

- Шард-ключ: { status: 1, user_id: 1 } (для пользовательских) и отдельная стратегия для гостевых
- Стратегия: Составной ключ с зонированием (zone sharding)

### Обоснование

1. Основные операции:
    - Создание корзины для гостя/пользователя
    - Получение активной корзины по session_id или user_id
    - Обновление корзины (добавление/удаление товаров)
    - Слияние гостевой и пользовательской корзин
    - TTL-очистка старых корзин

2. Почему выбран такой шард-ключ:
    - status в качестве первой части позволяет отделить активные корзины (95% операций) от заказанных и заброшенных
    - user_id как вторая часть обеспечивает, что все корзины пользователя находятся на одном шарде
    - Для гостевых корзин можно использовать отдельный шард-ключ { session_id: 1, status: 1 }

3. Преимущества:
    - Активные корзины (основная нагрузка) находятся в "горячем" шарде
    - Операции слияния корзин выполняются на одном шарде
    - TTL-очистка эффективна для архивной коллекции
    - Минимизация cross-shard операций при частых обновлениях

4. Примеры:

```javascript
// Создание индекса для шард-ключа (по статусу и пользователю)
db.carts.createIndex({ status: 1, user_id: 1 });

// Включение шардирования
sh.shardCollection("shop.carts", { status: 1, user_id: 1 });

// Вторичные индексы для поиска нужной корзины
// Поиск активной корзины по session_id (для гостей)
db.carts.createIndex({ session_id: 1, status: 1 });

// Поиск активной корзины по user_id (для авторизованных пользователей)
db.carts.createIndex({ user_id: 1, status: 1 });

// Поиск корзин по статусу для пакетной обработки
db.carts.createIndex({ status: 1, updated_at: -1 });

// TTL-индекс для автоматического удаления старых корзин
// Документ будет удален MongoDB, когда текущее время превысит значение в expires_at
db.carts.createIndex({ expires_at: 1 }, { expireAfterSeconds: 0 });

// Дополнительный индекс для слияния корзин
db.carts.createIndex({ user_id: 1, status: 1, updated_at: -1 });
db.carts.createIndex({ session_id: 1, status: 1, updated_at: -1 });

// Индекс для поиска заброшенных корзин (маркетинговые кампании)
db.carts.createIndex({ status: 1, created_at: 1 }, { partialFilterExpression: { status: "abandoned" } });
```
